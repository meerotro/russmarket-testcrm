## 2. Модель данных

```
Employee       id, full_name, position, avatar_url?
ShiftTemplate  id, name, start_time, end_time, color (blue|purple|mint), sort_order
Shift          id, employee_id, date, start_time, end_time, template_id?   unique(employee_id, date)
PublishedDay   date (PK), published_at
```

- Время хранится как `HH:MM`, дата — `YYYY-MM-DD`. Часовых поясов нет: график — это «настенное» время.
- `template_id = null` — «своя» смена.
- Длительность не хранится, а вычисляется (сервис на бэке, чистая функция на фронте).

## 3. Правила поведения

| Вопрос | Решение |
|---|---|
| Смен на сотрудника в день | Одна. Новая смена в занятой ячейке заменяет старую |
| Число на карточке шаблона | Счётчик смен по этому шаблону в видимом периоде. В макете 01 при пустом графике стоит 1 / 2 / 3, а на заполненных — 1 / 4 / 2 при восьми сменах «День»; считаем это неточностью макета |
| Длительность | Всегда из времени начала и конца. «08 - 18 / 8 ч» и «Вечер 15:00–23:00 · 9 ч» в макете — неточности |
| «агент · 24 ч» | Сумма часов сотрудника за видимый период, с учётом несохранённых правок |
| Цвет ячейки | По шаблону: Утро — голубая, День — сиреневая, Вечер — мятная. «Своя» смена — сплошная синяя |
| Ночные смены | Разрешены: конец ≤ начала означает «до следующего дня»; смена относится к дате начала. Начало = концу — ошибка |
| Формат времени в ячейке | «08 - 18»; если есть минуты — «08:30 - 18» |
| Клик по дате в шапке | Выделяет столбец (только видимых после поиска сотрудников) и открывает быстрое меню: шаблоны и «Очистить день» |
| Клик по ячейке | Выделяет её и открывает меню у ячейки: шаблоны, «Своя смена», «Очистить» |
| Множественное выделение | Ctrl/Cmd+клик — добавить или убрать; Shift+клик — прямоугольник от якоря; протягивание мышью от пустой ячейки. Esc — снять, Delete — очистить |
| Панель выделения | Заменяет строку поиска. Показывает реальные числа ячеек, сотрудников и дней. «Применить шаблон» — меню шаблонов; «Изменить» — время начала и конца для выделенных; «Очистить» — удалить смены; «Снять» — сбросить выделение |
| Своя смена | Поля «Начало» и «Конец» + «Поставить в выделенные». Кнопка неактивна без выделения или при некорректном времени |
| Drag-and-drop | Шаблон → ячейка (если ячейка входит в выделение — во все выделенные). Смена → другая ячейка — перенос, с Ctrl — копия; на занятую — замена |
| Покрытие | Число смен на дату по всем сотрудникам (поиск не влияет). 0 — розовая, ≥ 1 — голубая. Вычисляется из смен, отдельного состояния нет |
| Навигация по датам | В макетах её нет, в тексте задания — есть. Добавлены «‹ ›», подпись периода и «Сегодня» справа от переключателя. Неделя — пн–вс, месяц — календарный. Вид и дата хранятся в query-параметрах |
| Сохранить | Правки копятся в локальном черновике; «Сохранить» отправляет только изменения одним запросом |
| Опубликовать | Сохраняет черновик и помечает дни видимого периода опубликованными. Сохранённая правка в опубликованном дне возвращает день в черновик. Статус периода показан рядом с заголовком |
| Уход со страницы | `beforeunload` и guard роутера с подтверждением, если черновик не пуст |
| Авторизация | Не требуется по заданию. Как добавить — в README |

## 4. Фронтенд

```
resources/js/
  api/            client.ts (fetch + ApiError), schedule.ts (эндпоинты), types.ts
  lib/            time.ts (длительность, формат), dates.ts (периоды), cellKey.ts
  stores/         schedule.ts (Pinia)
  composables/    useCalendarPeriod, useCellSelection, useCoverage, useShiftDuration,
                  useDragAndDrop, useDebounce, useUnsavedGuard
  ui/             UiButton, UiSearchInput, UiSegmented, UiAvatar, UiTimeInput,
                  UiPopover, UiMenu, UiBadge, UiIcon
  components/
    layout/       AppLayout, AppSidebar
    schedule/     ScheduleToolbar, SelectionBar, ScheduleGrid, EmployeeCell, ShiftCell,
                  CoverageCell, TemplatesPanel, TemplateCard, CustomShiftForm, QuickAssignMenu
  pages/          SchedulePage, UiKitPage, HomePage
```

Стор `schedule`:

- состояние: `employees`, `templates`, `serverShifts` (то, что лежит на сервере), `draft`
  (`Map<"employeeId:date", ShiftInput | null>`, `null` — удаление), `publishedDays`, `cellErrors`;
- геттеры: `shiftAt(key)` (сервер + черновик), `isDirty`, `changeset` (`{ upsert, delete }`);
- действия: `load(from, to)`, `setShift`, `clearShift`, `moveShift`, `copyShift`, `applyTemplate`,
  `applyCustom`, `save`, `publish`, `discard`;
- правка, совпавшая с серверным значением, из черновика убирается — «грязным» график становится
  только при реальном отличии.

Компоненты страницы только отображают данные и вызывают действия стора. Компоненты `ui/` о
предметной области не знают.

## 5. API

Все ответы — JSON. Ошибки валидации — `422` в стандартном формате Laravel
(`{ message, errors: { "upsert.0.end_time": ["…"] } }`), фронт сопоставляет индекс с ячейкой.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/employees?search=` | Сотрудники, регистронезависимый поиск по ФИО |
| GET | `/api/shift-templates` | Шаблоны смен по порядку |
| GET | `/api/shifts?from=&to=` | Смены за период + опубликованные дни. Период не длиннее 62 дней |
| PUT | `/api/shifts` | Пакетное сохранение в одной транзакции |
| POST | `/api/schedule/publish` | Опубликовать период |

`PUT /api/shifts`

```json
{
  "upsert": [
    { "employee_id": 1, "date": "2026-11-10", "start_time": "07:00", "end_time": "15:00", "template_id": 1 }
  ],
  "delete": [
    { "employee_id": 2, "date": "2026-11-11" }
  ]
}
```

Правила: сотрудник и шаблон существуют; дата и время в нужном формате; начало ≠ концу; пара
`(employee_id, date)` не повторяется внутри запроса. Любая ошибка — ничего не сохраняется.
Ответ: `{ "data": [Shift…], "published_days": ["2026-11-10", …] }` по затронутым датам.

`Shift` в ответе: `id, employee_id, date, start_time, end_time, template_id, duration_minutes`.

## 6. Что не входит

Авторизация и роли, одновременная работа нескольких пользователей (последняя запись побеждает),
редактирование самих шаблонов, мобильная вёрстка.
